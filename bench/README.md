# モデル比較ベンチ

Ollama 上のモデルに Python の課題を解かせ、生成コードを自動採点する。

## 課題
1. バグ修正 (移動平均関数の off-by-one)
2. 仕様から実装 (`"1h30m15s"` を秒に変換)
3. リファクタリング (挙動を変えずに整理。元の関数との出力一致を 300 件で確認)
4. テスト生成 (うるう年判定。正解で通り、わざと壊した 3 実装を検出できるか)

## 使い方
```bash
python3 bench/selftest.py   # 採点自体の検証 (正解は満点、不十分なコードは減点になること)
python3 -u bench/bench.py   # モデルに課題を投げて採点 (MODELS と SAMPLES を編集または環境変数で指定)
```

`kubectl` で `llm` namespace の Ollama に接続する。kubeconfig は `~/.kube/config-home` を使う。

## 注意
- **生成コードをローカルで実行する**。一時ディレクトリ内で、20 秒のタイムアウト付きだが、信頼できない出力は実行しない運用にすること。
- `ollama run` は出力を約 80 桁で自動折り返しし、コードを壊す。`--nowordwrap` が必須 (bench.py で指定済み)。
- 採点環境は Python 3.8 のため、型ヒントの新しい構文で不当に落ちないよう `from __future__ import annotations` を付与している。
- 各課題 2 回では、バラつきの大きいモデルの評価には少ない。`SAMPLES` を増やして再評価するとよい。
- 補完 (FIM) の品質は対象外。
