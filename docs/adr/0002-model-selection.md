# ADR-0002: モデル選定方針

- ステータス: 採用 (実機での性能比較後に見直す)
- 日付: 2026-10-18

## 背景
- 中国系以外のモデルを使いたい。
- CPU 推論では、メモリ帯域がボトルネックになるため、アクティブパラメータの少ない MoE モデルや小型モデルが有利。
- 当初提案した `granite4` と `gpt-oss:20b` は最新ではなかった。2026-10 時点で Ollama 公式ライブラリを確認し直した。

## 決定
既定の構成は次のとおりとする (`scripts/models.txt`)。

| 用途 | モデル | 理由 |
|---|---|---|
| チャット・編集 | `granite4.2:8b` | IBM、Apache 2.0。Granite 4.2 は 2026 年 8 月公開で、4.1 より新しい。 |
| コード補完 (FIM) | `starcoder2:3b` | BigCode。更新は約 2 年前だが、後継が見つからず、FIM 用の軽量モデルとして他に適当なものがない。 |

メモリに余裕がある場合に有効化する選択肢 (コメントアウト済み):
- `gpt-oss:20b`: OpenAI、MoE、約 14GB。16GB 以上のメモリが必要。現役だが 2025 年世代。
- `gemma4:e4b`: Google、軽量。
- `phi4-mini`、`phi4`: Microsoft。

## 検討した代替案と却下理由
- **Microsoft Phi 系を既定にする**: 最新の Phi-4 系は 2025 年世代で、Gemma 4 や Granite 4.2 より古い。`phi4` は 14B の dense モデルで CPU では遅い。コーディング専用版がなく、ベンチマークのデータ汚染を疑う声もある。軽量な `phi4-mini` はサブ用途の候補として残す。
- **Codestral**: FIM の評価は高いが、非商用ライセンス (MNPL) のため既定にしない。
- **Qwen3-Coder など**: 要件 (中国系以外) により除外。
- **Laguna XS 2.1** (33B 中アクティブ 3B の MoE、コード特化): Ollama に存在するが、提供元を確認できていないため保留。

## 実測結果 (2026-10-18)
Worker VM: 6 vCPU、CPU タイプ `host` (AVX2 有効)、メモリ 20GiB。Ollama の limits は cpu 5 / memory 10Gi。

| モデル | 生成速度 | プロンプト処理 | 備考 |
|---|---|---|---|
| `granite4.2:8b` | 約 5.9 tokens/s | 約 25 tokens/s | 1407 トークンの生成で約 4 分。推論モデルのため出力が長くなる。 |
| `starcoder2:3b` | 約 18.6 tokens/s | 約 55 tokens/s | 補完用途には実用的な速度。 |

- `--think=false` を指定しても `granite4.2:8b` の出力が長くなったため、思考の抑制が効いているかは未確認。
- 計測時の注意: 起動直後 1 回の計測であり、プロンプトの内容も 1 種類のみ。参考値として扱う。

## 未検証の事項
- `gemma4:26b` が MoE (A4B) 版かどうか。
- 3700X での各モデルの実測速度と品質。クラスタ稼働後に `ollama run <モデル> --verbose` で `granite4.2:8b`、`gemma4:e4b`、`phi4-mini` を同一プロンプトで比較し、このADRを更新する。
- Granite、Gemma、Phi の情報の一部は第三者サイトによる。モデルの存在とサイズは ollama.com/library で確認したが、性能比較は未確認。

## 結果
- モデルの追加・変更は `scripts/models.txt` の編集と `make models` で行える。
