# ADR-0010: Ollama のコンテキスト長を 8192 にする

- ステータス: 採用
- 日付: 2026-10-20

## 背景
- Continue のチャットで、数ターン後にモデルが前の会話を踏まえない回答をする (「リセットされる」ように見える)。
- Ollama の起動ログは `default_num_ctx=4096` で、`OLLAMA_CONTEXT_LENGTH` は未設定だった。
- 入力が `num_ctx` を超えると、Ollama は警告を出さずに古い部分を切り捨てる。
  切り捨てで先頭が変わると、前回とのプレフィックスが一致せず、毎ターン全文を再処理する。
  (Ollama の切り捨てについては第三者の資料による。Continue 固有の挙動は未確認。)

## 検証
同じ約 6000 トークンの入力 (`granite4.1:8b`) を、設定の前後で送り、処理されたトークン数を比べた。

| `num_ctx` | 処理されたトークン数 | pp |
|---|---|---|
| 4096 (既定) | 2050 | 25.8 tokens/s |
| 8192 | 6179 | 21.7 tokens/s |

- 4096 では、入力の約 3 分の 2 が切り捨てられていた。8192 では全文が処理された。
- 長い入力では attention の計算量が増え、pp は少し下がる。
- チャット (`granite4.1:8b`、6.9GB) と補完 (`qwen2.5-coder:3b`、2.4GB) を 8192 で同時にロードして、メモリ使用量は 10.5GiB / 14GiB で、再起動もなかった。

## 決定
- Deployment に `OLLAMA_CONTEXT_LENGTH=8192` を設定する。
- Continue の `config.yaml` でも、チャット用モデルに同じ値の `contextLength` を設定する (`docs/vscode-continue.md`)。

## 限界・注意
- 8192 でも、Continue が大きなファイルやツール定義を送れば、再び切り捨てが起きうる。足りない場合は 16384 を試す。
  ただし KV キャッシュは文脈長に比例して増える (Granite で 8192 のとき約 1.3GB)。メモリ 14Gi には余裕があるが、`gpt-oss:20b` など大きなモデルでは別途確認が必要。
- 「Continue の UI でチャット履歴そのものが消える」症状は、この変更では直らない。症状が「モデルが忘れる」ことは、確認済み。
- 検証は Ollama への直接入力で行った。Continue からの実際の会話での改善は、利用者が確認する。
